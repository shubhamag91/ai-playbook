## Core Principles

<CardGrid>
  <Card title="Start with the outcome, not the tool" icon="target">
    Define what you need done before choosing a model or platform. Claude for deep analysis, GPT-5.5 Instant for quick tasks, local Llama for privacy, Cursor for coding. The best tool is the one that gets the job done efficiently.
    
    💡 **Tip:** Match task complexity to model cost. Use instant models ($0.05/1M) for 70% of work. Use frontier models ($3-15/1M) only for hard reasoning.
  </Card>
  <Card title="Iterate aggressively" icon="refresh">
    Your first prompt is a hypothesis. Treat every AI interaction as a conversation — refine, add context, push back, ask for alternatives.
    
    💡 **Tip:** In Cursor: start broad, then narrow constraints. In Claude API: use markdown blocks to separate context. With agents: break the goal into discrete steps with feedback loops.
  </Card>
  <Card title="Always verify outputs" icon="warning">
    LLMs hallucinate confidently. Treat outputs as a strong first draft from a smart but fallible assistant — always fact-check critical claims.
    
    💡 **Tip:** Perplexity cites sources. NotebookLM grounds answers in your documents. For agents: require human approval on irreversible actions.
  </Card>
  <Card title="Own your data layer" icon="database">
    The real moat is proprietary data, not the model. Build pipelines to ingest, index, and retrieve your documents. RAG + local embeddings beats raw API calls.
    
    💡 **Tip:** LlamaIndex for ingestion. Chroma or Pinecone for retrieval. Prompt caching for repeated queries (50% cost savings).
  </Card>
  <Card title="Build in guardrails and monitoring" icon="shield">
    For production systems: add input validation, output filtering, human review for high-stakes decisions. Never deploy raw LLM output in sensitive domains.
    
    💡 **Tip:** LangSmith for tracing. Structured output (JSON schemas) for parsing. Human-in-the-loop for hiring, medical, financial decisions.
  </Card>
  <Card title="Use agents strategically (not universally)" icon="bot">
    Agentic AI (Cursor, Claude Code, multi-step workflows) excels at well-defined, bounded tasks. But agents make mistakes. Use them for code generation, data research, content drafts — not for irreversible decisions.
    
    💡 **Tip:** Agent loops work best with: clear goals, 3-5 step depth max, human review gates, error handling.
  </Card>
  <Card title="Stay genuinely curious" icon="lightbulb">
    The AI landscape changes monthly. Experiment with new models (Claude 4.7, reasoning models), new tools (Grok 3, Aider), new techniques (prompt caching, structured output). Share what you learn.
    
    💡 **Tip:** Spend 2 hours/week experimenting. Try: new models via API, local inference with Ollama, the latest open-source release on Hugging Face.
  </Card>
</CardGrid>

## AI Safety & Ethics (May 2026 Update)

### Why AI Safety Matters Now

AI systems are rapidly becoming more capable and autonomous. By May 2026:
- Agentic systems autonomously execute sequences of actions (code, API calls, browser automation)
- Reasoning models spend compute 'thinking' through complex problems
- Real-time multimodal AI processes live video/audio streams
- Models are deployed in critical domains: healthcare, finance, hiring

Safety research ensures these systems remain beneficial, controllable, and aligned with human values — especially as autonomy increases.

### Key Concepts

**Alignment** — Ensuring AI systems pursue goals humans actually intend. The paperclip maximizer is a toy example. Real examples: optimizing for click-through rate instead of user well-being, optimizing hiring metrics instead of actual job performance.

**Agentic AI Safety** — New in 2026. Agents taking multiple steps to reach goals creates new risks: hallucinated URLs, incorrect API calls, data leaks. Requires: step-level validation, human approval gates, rollback mechanisms.

**Real-Time Safety** — Grok 3 and live multimodal AI introduce new safety challenges. Models responding to real-time events (trending topics, live video) can amplify misinformation faster. Requires: content filtering, provenance tracking.

**Interpretability** — Understanding what happens inside neural networks. We still can't fully explain why models produce certain outputs. Mechanistic interpretability research aims to change that by May 2027.

**Test-Time Compute** — Reasoning models (o1, DeepSeek R1) spend compute 'thinking.' This changes attack surfaces: adversaries can exploit longer chains-of-thought. Requires new red-teaming approaches.

**RLHF & Constitutional AI** — OpenAI uses RLHF (human feedback). Anthropic uses Constitutional AI (AI-generated feedback). Both techniques align LLMs with human preferences. Increasingly important as models grow more powerful.

**Red-Teaming** — Adversarial testing where teams try to make models produce harmful outputs. Anthropic, OpenAI, and Google do this before releases. Your production team should too.

**Bias & Fairness** — Models trained on internet data absorb biases. Critical in hiring, lending, criminal justice AI. Auditing for demographic disparity is essential before deployment.

**Regulation & Governance** — EU AI Act (2024) classifies AI by risk. US, UK, China all moving toward regulation. By 2027, most enterprises will operate under compliance frameworks.

### Practical Safety Tips for Builders (May 2026)

#### For Chat & Analysis Tasks
1. Never base hiring/lending/medical decisions on raw AI output — require human review.
2. Use source-citing tools (Perplexity, NotebookLM) for factual research.
3. For sensitive work: use privacy-respecting plans (enterprise, local) or delete prompts from logs.
4. Ground responses in documents (RAG) to reduce hallucination.

#### For Agents & Autonomous Systems
5. Add step-level validation — check each agent action before executing.
6. Require human approval for: API calls to production systems, financial transactions, external communications.
7. Set agent depth limits (3-5 steps max) to prevent runaway loops.
8. Log everything — use LangSmith or similar for complete audit trails.
9. Implement rollback mechanisms — agents should be able to undo actions if needed.
10. Test adversarially — try to make your agent produce harmful outputs before users do.

#### For Data Privacy
11. Check data retention policies — enterprise/API plans are typically zero-retention.
12. For ultra-sensitive data: use local models (Ollama + Llama 4) on isolated hardware.
13. Anonymize before prompting — remove names, IDs, medical details.
14. Never share production data in chat UIs — use API with data disabled.

#### For Prompting
15. Set temperature conservatively (0.1-0.3) for factual tasks; higher (0.7-1.0) for creative tasks.
16. Use structured output (JSON schemas) to force machine-parseable responses.
17. Add explicit constraints: "DO NOT include names, medical details, or customer IDs in your response."
18. Specify failure modes: "If unsure, say 'I don't have enough information' rather than guessing."

#### For Model Selection
19. Match model to risk level: use frontier models (Claude 4.7) for high-stakes decisions; use cheap models (Instant, Haiku) for routine work.
20. For open-source: verify license compatibility before commercial use.
21. For local deployment: audit model for safety (known jailbreaks, biases) before production.

### What Still Needs Work (May 2026)

- **Interpretability remains hard.** We can't fully explain model decisions. Red-teaming is still the best safety practice.
- **Agentic safety is nascent.** Best practices still evolving. Expect tool-specific guidance to improve by 2027.
- **Real-time AI safety untested at scale.** Grok 3 and live reasoning models are early. Expect issues.
- **Regulation is fragmented.** US/EU/China have different rules. Multi-jurisdictional compliance is complex.

### The Honest Take

We're building increasingly capable systems without fully understanding them. The best we can do: stay paranoid, test aggressively, require human oversight, and adapt as we learn. By 2027, agentic AI and reasoning models will raise new questions we can't anticipate today.
